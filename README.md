表情包制作（轻量版）—— **AstrBot 原生插件**，直连 meme-generator 后端，
可与 GsCore 侧的 `core_plugin_memes` **共用同一个服务**（同一个 `MemeApiUrl`）。

## 为什么叫「轻量版」

GsCore 的 `core_plugin_memes` 有 **30 个文件 / 5052 行**（搜索、管理、统计、昵称、门控、
AI 知识库等一应俱全）。本插件保留**核心能力**，砍掉与 AstrBot 自身重复的部分：

- 代码量约 **1600 行 / 6 个模块**
- **不下载任何本地模板资源**（原生 GsCore 方案要下 2000+ 张图，这里直接用远程后端）
- 索引可缓存到本地，二次启动秒加载

## 安装

1. 把整个 `astrbot_plugin_meme_lite` 目录放进 `AstrBot/data/plugins/`
2. 重启 AstrBot，或在插件管理页点「重载」
3. 依赖：`httpx`、`Pillow`（AstrBot 环境一般已自带；缺失时用插件管理页的依赖安装）

首次启动会自动拉取表情索引（841 个约 15 秒），结果缓存到
`data/plugin_data/astrbot_plugin_meme_lite/meme_index.json`。

## 配置（插件管理页）

| 键 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `api_url` | **必填，无默认值** | 你自己的 meme-generator 后端根地址，例如 `http://127.0.0.1:2233`。留空时插件不工作 |

> ⚠️ **`api_url` 必须自己填**：本插件不自带、也不会写死任何公共后端，请填你自建的 meme-generator 后端根地址（末尾不要带 `/`）。未填时出图命令会提示「未配置后端地址」。
| `request_timeout` | `60` | 请求超时（秒） |
| `trigger_prefix` | 空 | 生成表情的触发前缀（示例 `bq`）。详见下方说明 |
| `cooldown_seconds` | `5` | 同会话生成冷却 |
| `auto_refresh_index` | `true` | 启动时刷新索引 |
| `index_cache_hours` | `24` | 索引缓存有效期 |
| `max_image_size_mb` | `5` | 素材图片上限，超出自动压缩 |
| `enable_stats` | `true` | 记录调用统计 |

> ⚠️ **`trigger_prefix` 一定要填**
>
> 留空时，**任何消息只要以某个表情关键词开头就会触发**。而 841 个表情里有大量**单字/双字**关键词
> （`搓` `哈` `摸` `亲` …），群聊随口一句话就可能撞上：
>
> | 群友说的话 | 实际命中 | 后果 |
> |---|---|---|
> | 「**搓**破过好几次了」 | `twist`（关键词「搓」） | 素材不符 → 回一句提示到群里 |
> | 「**哈哈**哈哈哈」 | `kurogames_phoebe_haha` | 直接出图 |
>
> 而且素材不匹配时还会往群里回一句提示，比出图更扰民。
>
> **填了前缀（示例 = `bq`）后**，只有 `bq摸头` / `bq 摸头` / `bq亲` 这样**主动发**的消息才会出图：
>
> ```
> bq摸头          → petpet     ✅
> bq 摸头         → petpet     ✅（带空格也行）
> bq亲            → kiss       ✅
> 搓破过好几次了   → 不触发      ✅（无前缀，忽略）
> ```
>
> `/随机表情` 等命令**不受影响**，戳一戳联动（pokepro 命令位）也不受影响。

## 命令

> 前缀说明：`bq` 是插件自己的 `trigger_prefix`。**`bq表情列表` 与 `/表情列表` 都能用** ——
> 前者由插件的 catch-all 识别后转发给命令处理，后者走 AstrBot 原生唤醒前缀。
> 出图（`bq摸头`）只支持 `bq` 前缀。

**出图（核心）**
```
摸头                  ← 直接用发送者头像
摸头 你好             ← 带台词
摸头 自己             ← 显式指定用自己头像
摸头 @某人            ← 用被 @ 的人的头像
摸头 --circle true    ← 表情专属选项（用 /表情详情 查可用选项）
```

**随机**
```
/随机表情
/随机表情 @某人
```

**查询**
```
/表情列表                     ← 渲染表情总览图（可用 / 本会话禁用 / 全局禁用 三段）
/表情搜索 <词>                ← 按关键词/标签搜
/表情详情 <关键词>            ← 图片/文字需求、可选参数
```

**管理**
```
/禁用表情 <词>      /启用表情 <词>                      ← 本会话
/全局禁用表情 <词>  /全局启用表情 <词>                   ← 管理员
/表情黑名单                                              ← 查看全局禁用
/屏蔽表情 <词>      /解除屏蔽 <词>                       ← 不让别人拿我当素材
```

**统计 / 群开关 / 维护**
```
/表情统计 [n]                 ← 当日调用排行
/开启表情包 /关闭表情包 /表情包状态
/更新表情                     ← 管理员，刷新索引
/表情帮助                     ← 渲染帮助图（管理员多显示一栏全局命令）
```

> 帮助图与表情列表图都用 PIL 本地渲染（1100px 宽、深色编辑风），不依赖浏览器或 t2i 服务；
> 841 条表情出图约 3~4 秒、1MB 左右。渲染失败时自动回退成纯文字，不会没反应。

## 素材从哪来（重要）

一句话：**谁的头像被用，取决于你给的是哪种素材**，优先级从高到低：

| 顺序 | 来源 | 例子 | 用的头像 |
|---|---|---|---|
| 1 | 消息里**自带的图片** | 发图 + `bq摸头` | 你发的图本身 |
| 2 | **引用消息里的图片** | 引用一条带图的 + `bq摸头` | 被引用的那张图（v1.0.6） |
| 3 | **`自己`** | `bq摸头 自己` | 发送者（你） |
| 4 | **`@某人`** | `bq摸头 @张三` | **被 @ 的人**（支持多个 @，按顺序成为第 1/2 张） |
| 5 | **兜底** | `bq摸头`（啥都没给） | 发送者（你） |

> 所以 `bq摸头` 用你的头像不是 bug —— 是上表第 5 条的兜底。
> 想让别人的脸出现：`bq摸头 @他` 或 `bq摸头 自己 @他`（前者第 1 张就是他，后者你是第 1 张）。

> **引用消息的图**（v1.0.6）：引用的图片**不在**当前消息的 Image 段里 —— AstrBot 的
> aiocqhttp 适配器把被引用消息整条塞进 `Reply.chain`，chain 拿不到时只剩 `Reply.id`。
> 插件走框架自带的 `astrbot.core.utils.quoted_message.extract_quoted_message_images`：
> 先读 chain，chain 里没有再用 `get_msg` 回捞原消息。没有这一步时，引用图片会静默落空，
> 然后被第 5 条兜底成发送者头像 —— 看起来就像「引用的图没取到」。
>
> ⚠️ **v1.0.7 修的一个重要细节**：这个提取器在图片**已经缓存到本地**时返回的是**裸本地路径**
> （不是 http 链接）。原先 `fetch_image` 只认 `http(s)://` / `base64://` / `file://`，
> 裸路径会直接抛 `Request URL is missing an 'http://' or 'https://' protocol`，
> 用户看到的就是「有一张图片下载失败」。现在四种形态全认：http / base64:// / data: / 本地路径。

> **头像清晰度**：默认取 `q1.qlogo.cn` 的 640×640。但**动图（GIF）头像在 640 档会被 qlogo
> 退化成 40×40 的默认企鹅图**，插件会自动降到 140 档去拿真实的 100×100 动图（v1.0.3）。
> 所以看到企鹅头，才是真的取不到。

### 素材多了会怎样（v1.0.4）

**多出来的图/文字直接裁掉，只有"不够"才报错** —— 与 GsCore 侧 `extra_text_policy` /
`extra_image_policy = drop` 的默认行为一致。

这条很关键，因为**单字关键词会把后面的字吃掉**：

| 输入 | 命中关键词 | 剩余文本 | 处理 |
|---|---|---|---|
| `bq电死你 @张三` | `电`（zaoleipi，需要 1 图 0 文）| `死你` | 文字裁到 0 段 → 正常出图 ✅ |
| `bq摸头 你好 再见` | `摸头`（1 段文字）| `你好 再见` | 截成 1 段 |

修复前是严格校验（0 段文字收到 1 段就整单拒绝），所以 `电死你` 会失败。代价是多给的
文字会被静默丢弃 —— 想保留完整台词，就用该表情真正的完整关键词。

### 需要两张及以上头像的表情

841 个表情里有 **27 个要 ≥2 张图**（`揍` `击剑` `双喜` `白天黑夜` `3p` …）。这类会自动把人补齐：

| 输入 | 实际素材顺序 | 效果 |
|---|---|---|
| `bq揍 @张三` | `[你, 张三]` | **你揍他**（自动把你补到第 1 位） |
| `bq揍 自己 @张三` | `[你, 张三]` | 同上（显式写法，不会重复加你） |
| `bq揍 @张三 @李四` | `[张三, 李四]` | 两个人够了，不再补你 |
| `bq3p @张三 @李四` | `[你, 张三, 李四]` | 3 图表情补到 3 个人 |

> **顺序规则**：多图表情里 **第 1 张是"施动方"**。实测 `揍`（beat_up）的模板是
> `image[0]` 站着打人、`image[1]` 倒地；所以 `@某人` 时补你在第 1 位 = 你打他。
> 想要反过来，就 `bq揍 自己 @张三` 之外再加一句说明 —— 或直接发两张图（顺序由你掌控）。
>
> 人头不够时会直接告诉你还差几个（带 💡 提示怎么补）。

顺带说明：AstrBot 会把非首位的 `@` 拼成 `@昵称(QQ号)` 写进消息文本，
插件会先把这段文本剔掉再当台词用（v1.0.1 修复），否则要求「0 段文字」的表情会误判素材不符。

## 与 pokepro 联动（戳一戳出图）

pokepro（专业戳一戳）的「**命令**」响应位可以填 `随机表情`：

```
戳一下 → pokepro 按权重选中「命令」响应 → 伪造「@机器人 随机表情」事件入队
       → 本插件响应 → 出图
```

这样**不需要 GsCore 适配器**，也**不会多出一条回复**（完全融入 pokepro 的加权响应池）。

> ⚠️ 注意：pokepro 伪造的消息是 `@机器人 + 命令`，所以出图用的是**机器人头像**。
> 若想用「戳的人」的头像，需要改 pokepro 的 `respond_cmd`（把 `At(qq=evt.get_self_id())` 换成发起者）。

## 实现要点

| 模块 | 职责 |
|---|---|
| `core/models.py` | `MemeInfo` / `MemeOption`，含 Python 版与 Rust 版 info 的归一化 |
| `core/client.py` | 后端探测、索引拉取与缓存、生成 |
| `core/store.py` | 个人/全局禁用、屏蔽、群开关、统计（JSON 持久化） |
| `core/parser.py` | 解析 `自己` / `@某人` / `--选项 值` / 台词 |
| `core/utils.py` | 头像与图片获取、超限压缩 |
| `core/render.py` | 帮助图 / 表情总览图的 PIL 渲染（移植自 core_plugin_memes） |
| `fonts/` | 内置中文字体子集（Noto Serif/Sans SC，SIL OFL），不依赖系统字体 |
| `main.py` | 命令注册与调度 |

- **后端双版兼容**：`/memes/keys` 200 判为 Python 版，`/meme/keys` 200 判为 Rust 版；
  info 结构差异（Python 版参数藏在 `params_type` 里）已在 `models.py` 归一化。
- **索引缓存**：`refresh_all()` 并发 32 路拉取（841 条约 15 秒），结果落盘，二次启动直接命中。
- **关键词匹配**：长关键词优先的前缀匹配（`摸摸你的头` 会命中 `摸摸` 而不是 `摸`）。
  - **无前缀时要求关键词 ≥2 字** —— 避免「搓」「哈」这类单字词撞上正常群聊
    （否则「搓破过好几次了」会命中 `twist`）
  - **带前缀时单字也放行**（`bq搓` ✅ / `bq吃` ✅，属于主动调用）
- **自动触发失败静默**：无前缀自动命中但素材不满足时**不往群里回提示**；
  只有带前缀主动调用时才回「需要图片 X 张…」这类说明。
- **字体自带**：`fonts/` 里是 GB2312 + 当前表情关键词用字的 Noto 子集（serif 5.5MB / sans 3.9MB），
  优先加载，系统字体仅作后备 —— 换到没装中文字体的机器也不会渲染成方块。
  新增表情后若出现方块字，用 `fonts/build_subset.py` 重新生成（见 `fonts/README.md`）。

## 已知限制

- 只实现 aiocqhttp 平台的图片发送（其它平台未测试）。
- 统计只有"当日"维度，保留最近 7 天。
- 不含 GsCore 版的「昵称记录」「AI 知识库注册」「NSFW 门控」等模块。

## 🔐 黑白名单（v1.0.8）

插件配置页 →「黑白名单」，语义对齐 astrbot_plugin_media_parser：

- 优先级：**管理员 > 个人白名单 > 个人黑名单 > 群组白名单 > 群组黑名单**
- 白名单启用但未填名单 = 只允许管理员；未命中任何规则时：白名单启用=拒绝，未启用=放行
- 名单只限制**表情生成**（关键词自动触发、前缀生图、随机表情）；帮助 / 列表 / 统计 / 管理命令不受限
- 被拒时：**全静默**——不回复任何文案（自动触发、前缀生图、随机表情都一样），只在服务端日志留一条 debug 记录

## 🌐 连接后端（v1.0.11）

`api_url` 只填**根地址**，不要带 `/v1`、`/api` 之类路径前缀，也不要带结尾斜杠：

```
✅ https://meme.xlinxc.cn
❌ https://meme.xlinxc.cn/v1
❌ https://meme.xlinxc.cn/memes
```

顺带一提，后端根路径 `/` 返回 `{"detail":"Not Found"}` 是**正常的**（服务端没定义根路由），
要验证请访问完整路径：

```
https://meme.xlinxc.cn/memes/keys     # Python 版后端
https://meme.xlinxc.cn/meme/keys      # Rust 版后端
```

### 手机端 / 容器内「无法连接后端」怎么排查

v1.0.11 起，报错会带上真实原因，例如：

- `…/memes/keys 返回 HTTP 404；…/meme/keys 返回 HTTP 404` → `api_url` 多了路径前缀
- `…连接失败（ConnectError: …）` → 网络层不通（DNS / 防火墙 / 代理）
- `…连接失败（ConnectTimeout: …）` → 能解析但连不上，多半是 IPv6 不通

手机浏览器能打开、插件却连不上，最常见的原因是**域名解析优先给了 IPv6，而运行环境
的 IPv6 出不去**（浏览器会自动回退 IPv4，Python 的 httpx 不会）。
v1.0.11 已改为**强制 IPv4 出站**，这类环境无需额外配置。
